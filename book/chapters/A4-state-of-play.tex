\chapter{State of Play, September to November 2026}
\label{app:stateofplay}

The names, prices and limits below record the situation between September and
November 2026. Each section carries the date on which its facts were checked,

\textbf{Around 2,200 euros}, a 64\,GB Framework Desktop (2,209 euros on
22 October 2026) or a 64\,GB Mac mini runs a 30B model usefully: the entry
point for serious local work. \textbf{Around 3,000 to 4,000}, a 128\,GB
machine (the Framework at 3,889 euros, a DGX Spark, a Mac Studio) opens 70B
models, where open weights become competitive for scoped work. For a group,
one such machine can serve several people. \textbf{A separate graphics card}
is the choice if you also need to train, want the fastest prefill on long
agent prompts, or want maximum speed on models under 32\,GB. Its power draw
affects cooling, the electricity bill and where the machine can live.

\textbf{Memory bandwidth and power, by device.} Read on 22 October 2026 from
the makers' pages named in parentheses. Apple M5: 153\,GB/s. M5 Pro:
307\,GB/s. M5 Max: 460\,GB/s with the 32-core GPU and 614\,GB/s with the
40-core GPU, which is also the only M5 Max with 128\,GB. M5 Ultra: 1.2\,TB/s
with 96, 256 or 512\,GB. The Mac mini now starts with an M6 at 153 or
170\,GB/s (Apple, technical specifications for Mac Studio, MacBook Pro and
Mac mini). NVIDIA DGX Spark: 128\,GB of unified memory on a 256-bit bus,
273\,GB/s, a 240\,W power supply and a 140\,W chip (NVIDIA, DGX Spark page).
NVIDIA RTX PRO 6000 Blackwell: 96\,GB GDDR7, 1,792\,GB/s, 600\,W maximum
(NVIDIA, RTX PRO 6000 page). NVIDIA GeForce RTX 4060 Ti: 8 or 16\,GB GDDR6 on
a 128-bit bus, 160 to 165\,W (NVIDIA, RTX 4060 Ti page). That page gives no
bandwidth figure; the 128-bit bus is a quarter of the professional card's.
NVIDIA's page for the RTX 5060 Ti could not be read by script, so its figures
are not given here.

\section{Models}

Checked on 22 October 2026 on Hugging Face and the Ollama library. Sizes are
total parameters; mixtures of experts also give active ones
(\Cref{ch:hardware}).

\begin{itemize}
  \item \textbf{Gemma 4} (Google). Dense 12B: \code{gemma4:12b}, 7.7\,GB on
    Ollama at four bits, 256K context. It has 26B and 31B siblings and small
    \code{e2b} and \code{e4b} builds. Apache-2.0, which matters for the
    licence discussion in \Cref{ch:aireadydata}.
  \item \textbf{Qwen 3.8 27B} (Alibaba). Dense, Apache-2.0, 262K context,
    17\,GB at Q4\_K\_M; the open release behind \textcite{willison2026qwen38}.
    No open-weight ``Qwen 3.7'' exists on Hugging Face under the Qwen
    organisation; the 3.7 names are hosted models. A 2.4T-parameter mixture
    with 95B active was released beside the 27B and is a server model.
  \item \textbf{Qwen3-30B-A3B-Instruct-2507} (Alibaba). Mixture of experts:
    30B total and about 3B active (128 experts, 8 per token), with 4
    key-value heads. It is the model in the serving example of
    \Cref{ch:hardware}. The plain \code{Qwen3-30B-A3B-Instruct} id does not
    exist.
  \item \textbf{Kimi K2.7} (Moonshot). Mixture of experts, 1T total and 32B
    active, so a hosted model for most readers; not a 12--30B model.
  \item \textbf{Embedding and reranking.} \code{bge-m3} and
    \code{bge-reranker}. \textbf{Transcription.} Whisper.
\end{itemize}

\section{Harnesses}

Checked on 22 October 2026. In the terminal: Claude Code, OpenCode, Codex,
Gemini CLI, Copilot CLI and Aider. Inside code editors: Cline and Continue,
both open source. GitHub Copilot in VS Code includes an agent mode. Cursor is
a proprietary editor built around an agent. Posit Assistant ships with
Positron, Posit's data-science editor, from version 2026.07, and replaces the
earlier Positron Assistant; Positron is distributed under Posit's own licence,
not an open-source one. The R readership will meet the last of these first.
\Cref{app:tutorials} links to the open-source ones. Of the terminal harnesses
used in this book, OpenCode (MIT) and Codex (Apache-2.0) are open source;
GitHub's API reports no licence for Claude Code, which is commercial (checked
2 November 2026). Claude Code has offered a sandbox with file-system and
network isolation since 20 October 2025, switched on with \code{/sandbox}
\parencite{anthropic2025sandboxing}; it was not tested for this book. MCP, the protocol through which harnesses reach tools, is an
open specification, donated in 2025 to the Linux Foundation's Agentic AI
Foundation \parencite{liu2026claudecode}.

\begin{sloppypar}
\textbf{Rules and memory files.} Read on 4 November 2026 from each tool's
documentation (\Cref{ch:agentic}). Claude Code 2.1.318 loads \code{CLAUDE.md}
from the working directory and every directory above it. It also loads a user
file at \code{\textasciitilde/.claude/CLAUDE.md}, an organisation-wide file
(\code{/etc/claude-code/CLAUDE.md} on Linux; on macOS a \code{ClaudeCode}
folder under \code{/Library/Application} \code{Support/}), a gitignored
\code{CLAUDE.local.md} and topic files under \code{.claude/rules/}. It reads
\code{AGENTS.md} when there is no \code{CLAUDE.md} or \code{CLAUDE.local.md}
in the working directory or above it. Its auto memory is a directory per
repository, \code{\textasciitilde/.claude/projects/}\allowbreak\code{PROJECT/memory/}, holding
one Markdown file per memory and an index, \code{MEMORY.md}. The first 200
lines or 25\,KB of the index are loaded at the start of every session; the
topic files are read on demand. \code{/memory} lists and opens these files and
switches auto memory off or on, and \code{autoMemoryEnabled} set to false in a
project's settings turns it off there. The directory is local to the machine
and is kept when old transcripts are deleted. OpenCode 1.17.11 reads
\code{AGENTS.md} in the project root and
\code{\textasciitilde/.config/opencode/AGENTS.md} for all projects. It falls
back to \code{CLAUDE.md} and \code{\textasciitilde/.claude/CLAUDE.md}, and
takes further files from an \code{instructions} list in \code{opencode.json};
\code{/init} writes or improves \code{AGENTS.md}. Codex 0.162.1 reads
\code{AGENTS.md}, or \code{AGENTS.override.md}, from
\code{\textasciitilde/.codex/} and from the project root down to the working
directory. The files are concatenated from the root downward and cut at
32\,KiB by default; its page on these files describes no memory beyond them. None of the three
enforces what the files say (\Cref{ch:firstsession}).
\end{sloppypar}

\section{Ollama and local tooling}

Checked on 22 October 2026. The chapters name the lasting tools and point
here for the defaults and tags of the day.

\begin{itemize}
  \item \textbf{Context defaults.} Ollama sets the default context length by
    the GPU memory available: 4K below 24\,GiB, 32K from 24 to 48\,GiB and
    256K at 48\,GiB and above. Its cloud-hosted models default to their
    maximum (docs.ollama.com/context-length, read 22 October 2026). A larger
    context needs more memory for the KV cache (\Cref{ch:hardware}).
  \item \textbf{Context for agents.} The same page advises at least 64,000
    tokens of context for agents, web search and coding tools. Set it for the
    whole server with \code{OLLAMA\_CONTEXT\_LENGTH=64000 ollama serve}, or
    per model in a Modelfile.
  \item \textbf{A coding model to start from.} The listing in \Cref{ch:stack}
    uses a \code{MODEL} placeholder because tags date. On 22 October 2026 the
    Ollama library's \code{qwen3-coder:30b} stood in for it: 19\,GB at four
    bits, 256K context, a 30B mixture with 3B active. The newer entry is
    \code{qwen3-coder-next}; the dense alternative the workshop used is
    \code{gemma4:12b} (7.7\,GB).
  \item \textbf{Apple silicon.} MLX builds are the native route on Apple
    silicon: LM Studio runs MLX and llama.cpp under the hood, and Ollama tags
    them \code{-mlx}; the session in \Cref{ch:firstsession} was completed with
    \code{gemma4:12b-mlx-32k}, a four-bit (nvfp4) build saved with 32,768
    tokens of context. Ollama's \code{cloud} tags run on Ollama's servers.
    A prompt sent to one leaves the machine (\Cref{ch:localfirst}).
  \item \textbf{Open WebUI.} BSD-3-Clause up to version 0.6.5. From 0.6.6
    (April 2025) its licence adds a branding clause for deployments of more
    than fifty users, so it is no longer under a plain open-source licence
    (Open WebUI, licence page).
  \item \textbf{Prompt caching.} Hosted APIs keep the unchanged prefix of a
    prompt and charge less to read it again. Anthropic's documentation prices
    a cache read at a tenth of the base input price, with lower rates on some
    models (Anthropic, prompt-caching documentation). This is why an agent's
    long, repeated prompts cost less than their token counts suggest
    (\Cref{ch:agentic}).
\end{itemize}

\section{Subscription limits}

Checked on 22 October 2026 at Anthropic's help centre. Paid consumer plans
(Pro, Max, Team) have two limits: a session limit that resets every five
hours and a weekly limit. Use of the chat interface, Claude Code and the
desktop application all count against the same allowance. The units are not
published as tokens, and the allowance depends on the model, the features and
the reasoning effort chosen, so no token figure is given here. A single agent
turn re-sends the whole session, which is why one large refactor can use up a
window (\Cref{ch:agentic}). Other vendors ration in similar ways and publish
their own pages; check them before choosing a plan.

\textcite{wickham2026tokencost}, writing on 3 November 2026, reports a
SemiAnalysis estimate that a 200-dollar monthly plan returns between 2,000 and
10,000 dollars of tokens at API prices. Such plans, he notes, are sold to
individuals and small businesses, not to enterprises. His own costing of
self-hosting Kimi K3 (\Cref{ch:localfirst}) starts from a recommended server
of eight GB300 GPUs at about 550,000 dollars. With interest, colocation, power
and bandwidth it comes to about 23,000 dollars a month. At 75 per cent
utilisation that is about 0.25 dollars per million tokens, against a blended
1.13 dollars at the dearer providers. He calls the analysis crude and says it
leaves out the cost of training the model.

Anthropic's AI for Science programme, begun in May 2025, gives free credits
for its models to researchers on selected projects. On 28 October 2026 it
named 20 funders, institutions and research projects that will distribute or
use the credits, among them the US National Science Foundation, EMBL and the
Wellcome Sanger Institute, and the company sells a discounted Team plan to
scientists \parencite{anthropic2026aiforscience}. The page gives neither the
amounts nor the selection criteria (\Cref{ch:scientificworkflow}).
